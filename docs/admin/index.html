Technical notes

For whoever maintains the server. Nothing here is needed to use the connector — that is all on the main guide.

How it is deployed

A Python service on the same VPS as the stgconsulting.com site, behind its own nginx virtual host and its own TLS certificate. Nothing it does touches the existing site's configuration.

AI tool  ──HTTPS──▶  nginx                ──▶  127.0.0.1:8080  ──▶  Google APIs
                     mcp.stgconsulting.com      seo-analytics-mcp     Search Console
                     own cert, own vhost        systemd, user seomcp  GA4

One service account serves every teammate, so there is no per-user identity mapping and no OAuth to maintain. The unguessable path segment is the access control.

Why it is built this way

  • Its own user rather than www-data, so a file-read flaw in the Next.js site cannot reach the Google credential.
  • Its own certificate. Expanding the existing one would have re-issued the certificate the live site depends on.
  • No default_server — that stays with the main site, so a mistake here cannot capture its traffic.
  • Memory capped at 512 MB, so a runaway query kills this service rather than letting the OOM killer pick the larger Next.js process.
  • A service account rather than a personal token. The earlier personal OAuth token died after 55 days with invalid_grant, and only one person could have restored it.
  • uv-managed Python 3.13. The box ships 3.14, which has no grpcio wheels, so GA4 would have needed a source build.
  • Read-only by policy: in service-account mode the sitemap-submitting tool is unregistered rather than merely blocked.

Runbook

Status and logs

systemctl status seo-analytics-mcp
sudo journalctl -u seo-analytics-mcp -n 50 --no-pager
curl -s https://mcp.stgconsulting.com/healthz

Restart

sudo systemctl restart seo-analytics-mcp

Update to the latest release

cd /opt/seo-analytics-mcp
sudo -u seomcp /usr/local/bin/uv pip install --python .venv/bin/python \
  --reinstall-package seo-analytics-mcp \
  "seo-analytics-mcp[http] @ git+https://github.com/zainsive/seo-analytics-mcp.git@main"
sudo systemctl restart seo-analytics-mcp

Rotate the link

Do this when someone leaves, or if the link reaches somewhere public. There is no per-person access, so rotating replaces it for everyone.

python3 -c "import secrets; print('/mcp/' + secrets.token_hex(16))"
sudo nano /opt/seo-analytics-mcp/.env     # update SEO_MCP_ENDPOINT_PATH
sudo systemctl restart seo-analytics-mcp

Update these pages

scp docs/index.html stg-vps:/tmp/d.html
ssh stg-vps 'sudo install -m 644 /tmp/d.html /var/www/mcp-docs/index.html'

Settings

All in /opt/seo-analytics-mcp/.env. Restart after any change.

SettingPurpose
SEO_MCP_SERVICE_ACCOUNT_JSONThe Google credential, base64-encoded. Base64 because a private key's newlines defeat most .env parsers
SEO_MCP_ENDPOINT_PATHThe secret path — the access control
SEO_MCP_ALLOWED_HOSTSPublic hostname. Without it every proxied request returns 421
SEO_MCP_TOKENSPer-person bearer tokens, label:token comma-separated. Built but not yet enabled
GSC_DEFAULT_SITESo nobody has to name the property
GA4_DEFAULT_PROPERTYSame for GA4. Not set yet
SEO_MCP_EXPORTS0 — no CSVs on a server nobody can browse
SEO_MCP_HOMECache and state directory
SEO_MCP_LOG_LEVELWARNING; use INFO while debugging

nginx directives that matter

proxy_buffering offWith nginx's default buffering the connector connects and then hangs forever
proxy_read_timeout 3600sThe 60-second default drops a live session mid-conversation

For anything else, call auth_status. It reports the credential mode, which APIs answer, what they expose, and the next step.

Open items

The main site's certificate will not renew. A renewal test found that the stgconsulting.com certificate cannot renew, because www.stgconsulting.com resolves to AWS rather than this VPS and validation there returns 403. It expires 8 December 2026 and would fail quietly around the 30-day mark, first appearing as browser security warnings on the marketing site.

Either point the www DNS record at 50.62.183.237, or drop www from that certificate if it is deliberately served elsewhere. This predates the connector and surfaced only because deploying it ran the test.

GA4 default not set. GA4_DEFAULT_PROPERTY is empty, so GA4 questions need a property ID until it is filled in. ga4_list_properties returns it.

Access is one shared link. No per-person revocation, and no record of who asked what. Per-person bearer tokens are built and tested but not enabled, pending confirmation that claude.ai connectors can send a custom header.
